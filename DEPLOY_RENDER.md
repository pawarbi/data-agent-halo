# Deploy HALO to Render

HALO is a FastAPI + LangGraph app: redirect (auth-code) sign-in, and a live
reasoning-graph UI driven by real trace events streamed over SSE. Every data
agent call runs as the signed-in user (RLS/CLS enforced).

## 1. Entra app registration (Fabric tenant)

Same as AXIS — a Web app registration in the **Fabric tenant**:
1. App registrations → New (or reuse) → note **Application (client) ID** + **Directory (tenant) ID**.
2. Authentication → Add platform → **Web** → redirect URI =
   `https://<your-app>.onrender.com/auth/callback`  (exact match; add the real host after step 2).
3. API permissions → Power BI Service → Delegated → `DataAgent.Execute.All` → **Grant admin consent**.
4. Certificates & secrets → New client secret → copy the **Value**.

(You can only fill the exact redirect URI once you know your Render URL — deploy first with a
placeholder, then update both the Render env var and the Entra redirect URI to match.)

### Test the registration before deploying

The redirect flow is the one part `run_local.py` does not exercise, and it is where
deploys usually fail. You can test it on your own machine first, which is much faster
than debugging it on Render:

1. Add a **second** redirect URI to the same app registration:
   `http://localhost:8000/auth/callback`. Entra allows http for localhost.
2. Set the four variables and start the real hosted server, not `run_local.py`:

   ```
   HALO_CLIENT_ID=<app id>
   HALO_TENANT=<tenant guid>
   HALO_CLIENT_SECRET=<secret value>
   HALO_REDIRECT_URI=http://localhost:8000/auth/callback
   ```
   ```
   python server.py
   ```
3. Open `http://localhost:8000`, click **Sign in**, and confirm you land back signed in
   and a question returns data.

If that works, the same registration works on Render once you swap `HALO_REDIRECT_URI`
and the Entra URI to the `https://<app>.onrender.com` form. Put those four values in
`.env` rather than your shell if you prefer; `server.py` reads the environment, so
export them or use `run_local.py`'s loader as a reference.

Common failures, all seen before:
- `AADSTS50011` — the redirect URI does not match Entra **exactly**, trailing slash included,
  or `HALO_CLIENT_ID` is wrong (the Azure CLI's own client id will not have your URI).
- `AADSTS7000215` — invalid secret, usually the secret **ID** pasted instead of its **Value**,
  or it has expired.
- Signed in but every agent returns 401 — `DataAgent.Execute.All` is missing admin consent.

## 2. Push to a Git repo

Needed at runtime: `server.py`, `halo_core.py`, `index.html`, `requirements.txt`,
`render.yaml`. The rest (`test_local.py`, `dev_local.py`, `run_local.py`,
`probe_agents.py`) are development tools and are harmless to include.

Never commit `.env` or anything holding the client secret or the model API key.
The `.gitignore` covers `.env`, `or.txt`, `*.key` and `secrets*`.

## 3. Create the Render service

- render.com → New → **Web Service** → connect the repo. `render.yaml` is detected.
- Or manually: Runtime **Python**, Build `pip install -r requirements.txt`,
  Start `uvicorn server:app --host 0.0.0.0 --port $PORT`.

## 4. Set environment variables (Render → Environment)

| Key | Value |
| --- | --- |
| `HALO_CLIENT_ID` | app (client) id |
| `HALO_TENANT` | Fabric tenant id (GUID) |
| `HALO_CLIENT_SECRET` | the secret Value |
| `HALO_REDIRECT_URI` | `https://<your-app>.onrender.com/auth/callback` |
| `OPENROUTER_API_KEY` | for classify/synthesize/validate |
| `HALO_MODEL` | (optional) model id |
| `HALO_LLM_BASE_URL` | (optional) any OpenAI-compatible endpoint; defaults to OpenRouter |
| `HALO_SESSION_SECRET` | random string (auto-generated by render.yaml) |
| `HALO_AGENT_TIMEOUT` | (optional) seconds per data-agent call, default 300 |
| `CLOUDMETRICS_URL`, `MANUFACTURING_URL`, `ECOMMERCE_URL` | (optional) override an agent's MCP endpoint |

Agents live in `AGENTS` in `halo_core.py`, one `agent(url, description, excludes)`
entry each; paste the MCP URL Fabric gives you. The GUIDs are already baked in as
defaults, so the `*_URL` vars are only needed to point at different agents without
a code change. The UI lays out however many agents there are, so nothing else needs
updating when you add one.

Without a model key the app still runs: routing falls back to keyword matching,
synthesis concatenates the per-domain results, and validation auto-passes. The
trace says which happened.

## 5. Sign in and run

Open the Render URL → **Sign in** → redirected to Microsoft → back to HALO.
Type a question → watch the graph light up and the trace stream as HALO routes,
calls agents in parallel, synthesizes, and validates — as your identity.

## Notes
- **Free tier sleeps** after inactivity; first request cold-starts (~30–60s).
  Warm it up before a demo, or use the $7/mo Starter to stay always-on.
- **Auth mode**: hosted → redirect (this). The same graph runs locally too; for
  local dev you'd swap to interactive/`DefaultAzureCredential`.
- **Cross-tenant**: users and Fabric are in the same tenant here, so no guest
  setup. The Render host tenant is irrelevant — only the auth tenant matters.
