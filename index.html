HALO

Hierarchical Agent Loop Orchestrator

HALO answers a question by deciding which of your Microsoft Fabric data agents should handle it, asking them in parallel, combining what comes back, and then judging its own answer — retrying if the answer does not hold up. Every query runs as the signed-in user, so Fabric enforces that person's row-level security. HALO never reads data under a service identity.

Where the name comes from

Hierarchical

Two levels. An orchestrator on top decides strategy; the domain agents below own the data and the SQL. The orchestrator never touches a table.

Agent

Each domain is a published Fabric data agent with its own semantic model, its own definitions, and its own access rules.

Loop

The validator is a real cycle, not a formality. A failed answer goes back to fan-out with a critique attached, bounded by MAX_RETRIES.

Orchestrator

It routes and stitches. It deliberately does not join across agents — see the limits below.

What each node does

  • classify — picks the agent(s) the question needs. A model reads each agent's description and exclusions; if no model is reachable it falls back to keyword matching, and the trace says which fired. It may also pick none: a greeting or an off-topic question stops here, listing what the agents do cover, without spending a query. Guessing the nearest agent instead costs real time and returns a non-answer dressed up as data.
  • gate — optional human approval before any data is touched (HALO_HITL=1).
  • fan_out — calls every routed agent concurrently, as you. On a multi-agent question each agent is told it owns only part of the question, so it reports what it has rather than substituting a proxy for what it does not.
  • synthesize — one result passes straight through; several are merged with each domain's figures and time period attributed.
  • validate — a judge that can send the whole thing round again with a critique folded into the next ask.

What makes it different

vs. one data agent

A single agent can only answer within its own model. HALO spans domains that were never designed to be queried together.

vs. managed orchestration

The control flow is yours: an explicit classifier, a real retry cycle, a human gate, and checkpointed state you can resume or replay.

Identity, not a service account

The user's own token reaches Fabric. RLS, CLS and sensitivity labels apply, and the audit log names a real person.

The trace is the product

Routing, per-agent timings, the retry and the judge's reasoning all stream live. You watch it think rather than trusting a black box.

Features

  • Parallel fan-out with per-agent live timing, and what the concurrency actually saved.
  • A bounded self-correction loop driven by an LLM judge.
  • Per-user identity end to end via Entra auth-code sign-in.
  • Any number of agents; the graph on the left lays itself out from the server's list.
  • Degrades instead of failing: no model key means keyword routing, concatenated synthesis and auto-pass, and the trace says so.
  • Checkpointed per-thread state, so a conversation can be resumed or replayed.

Honest limits

HALO stitches, it does not join. Cross-domain answers place each domain's figures side by side; there is no row-level join and no cross-domain arithmetic. Agents also carry different data ranges and different default periods, so a combined answer states each period rather than implying a like-for-like comparison. The data agents do the real work — NL to SQL, the semantic model, the security. HALO decides who to ask, and checks the result.
